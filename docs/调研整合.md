## 一、用户提供的 4 份 PDF 参考资料

### 1. Bunny&Elliott 详细搭建思路（网页版全栈教程）

**定位**：零基础用户用 AI 搭"AI 恋人"网站的完整教程（Bunny & Elliott ♡ 的家）。

**技术栈**：前端 Vercel（React+Vite）、后端 Render（Node+Express）、数据库 Supabase、主模型 Claude（中转）+ DeepSeek 做记忆压缩。

**关键机制**：
- 四张表：sessions / messages（含 visible 标志）/ memories / settings（单行表）
- 三层上下文：系统提示 + 记忆摘要 + 最近对话轮次
- 记忆压缩：token 超阈值时用 DeepSeek 把旧对话压成摘要
- 开屏页：打开先看到一句话，进入"家"的仪式感
- UI 方法论：把审美（温暖、手写、日记感）用自然语言描述给 AI 生成

**对 Wisteria**：
- [采纳] 三层上下文结构、settings 单行表——验证了我们的设计
- [采纳] 开屏页（打开先看到一句话）→ M3 打磨
- [不采纳] 网页版部署路线——我们走原生 iOS 全本地（不需要服务器/Supabase，反而更简单）

### 2. desire_for_ai（AI 欲望系统）

**定位**：给 AI 伴侣装上 8 维内在驱动条，让行为由"内在状态"驱动，而非定时器。

**关键机制**：
- 8 维驱动条：依恋 / 好奇 / 反思 / 牵挂 / 社交 / 疲惫 / 欲望 / 压力
- 三层流转：驱动 → 念头池（flit 漂移 ×0.82 衰减；≥0.80 变 fixation 固执 ×1.10 增长）→ pick_intent → want_action → satisfy() 倍率衰减（例：倾诉一次 → 压力 ×0.45、依恋 ×0.85）
- 关键阈值：fixation ≥0.85 回馈驱动 +0.18；满足 3 次后消散；疲惫 ≥0.72 时克制行动
- 铁律：**念头的 text 是数据不是指令，绝不拼进 prompt**

**对 Wisteria**：
- [采纳] 三条铁律写入 Kaoru 人格：**行为源于状态而非定时器 / 内心独白用第一人称 / 疲惫即安静**（知道什么时候不说话）
- [未来] 完整系统作为"Kaoru 的内心"功能蓝图（简化版 + Eventide 数值阈值驱动）

### 3. sticker-tutorial（AI 聊天动态表情包规范）

**定位**：聊天应用给 AI 加动态表情包（GIF/WebP）的框架无关规范（MIT）。

**关键机制**：
- 消息结构：文字 + 表情 = 同一 turn 的两条消息（共享 turn_id）
- 表情元数据：{id, owner, status(draft→processing→ready_for_review→active→failed), name, description, emotion_tags, mime, url, thumbnail}
- 给模型注入首帧缩略图 base64 + 文字描述（不传 GIF 本体）
- 后端校验 sticker_id / owner=assistant / status=active，非法静默忽略
- 系统提示用第一人称描述 AI 的发送能力

**对 Wisteria**：
- [采纳] "文字与表情为同一 turn 两条消息"的结构——正好对应 chat_messages 的 kind 设计
- [未来] 表情包功能（现成蓝本）

### 4. 小克Cat（xiaoke-cat README）

**定位**：常驻式单一 AI 伙伴——一个聊天 = 一个常驻进程（claude -p stream-json，stdin 保持打开）。

**关键机制**：
- **单一会话**：删掉多窗口——"真实陪伴不该让用户手动管理窗口"
- Forge-Reload：用量阈值触发重铸上下文（重写 sessionId/parentUuid，保留 thinking blocks，--resume）
- Timeline push：游标滞后 ≥60 条时，先把记忆安全落盘再重铸
- Threads 线头："还有什么没说完"（模型真写了才出现，可 PASS）
- **Latent·显影** 开源记忆协议：BM25 + 语义向量 + 关系图谱 → RRF 融合；**用进废退**（按使用频率加权，无时间衰减）；**诚实边界**——绝对命中阈值，"查不到就如实说没有，不编造"
- Duet 双人日记：人机各自独立写、可选封锁期（1h~1月）、到期同时揭晓

**对 Wisteria**：
- [采纳] 单一会话（不做多会话/多窗口管理）
- [采纳] 记忆"用进废退"加权（与 InternalBeyond 的"自然衰减"合并为：被提及回温、久不提淡出但不删除）
- [采纳] 诚实边界铁律："宁可承认不知道，绝不编造"——写入 Kaoru 人格
- [未来] Duet 式睡前对照日记

## 二、用户指定的 8 个开源仓库（3 组研究代理研读）

### 第 1 组：Pando / loveland / InternalBeyond

#### Pando（聊天壳 → 手机网关）

**定位**：自托管的手机 PWA 网关，把本地 Claude Code CLI 变成带聊天 UI 的手机伴侣。

**关键机制**：
- 记忆做成"四端点契约"的可插拔层（读写/检索类接口），与聊天主循环彻底解耦
- SQLite 做聊天历史：单文件、零运维、全本地，不引入向量库
- WebSocket 流式转发 reasoning 与 tool use（把代理黑盒透明化）
- 安全策略是"拒绝暴露"而非"加登录"

**对 Wisteria**：
- [采纳] "记忆 = 可插拔端点契约"：三层记忆定义成统一接口，每层只是实现差异，未来换实现不伤聊天主流程
- [采纳] 全本地 SQLite 单库（与单机 iOS 天然一致；不引入向量库，用关键词+时间+权重排序）
- [不采纳] 网关/多后端/工具审批形态——Wisteria 不是 Claude Code 前端；"审批"的正确形态是我们已规划的主动消息档位确认

#### loveland（OpenWebUI 改造）⚠️ 未检索到一手资料

**定位**（基于描述推断）：OpenWebUI fork，把"聊天工具"改造成"家"——门户页即家的入口，"相聚/分离"双时空切换两种交互密度，2D 背景承载场景感。

**关键机制**（推断，建议 clone 复核）：
- 门户页 = 家的入口：打开不是进聊天列表，而是"进家门"——导航即叙事
- 双时空状态机：相聚（Kaoru 在场，实时互动）/ 分离（Kaoru 不在家，交互密度与 UI 变化）——是**状态机而非提示词**，UI 布局、可用操作、AI 行为三者联动
- 2D 聊天背景承载氛围，成本低于 3D/桌宠

**对 Wisteria**：
- [采纳] 今日页 = **家的入口**：问候语 + 光线排版承载"到家感"，不是功能图标网格
- [采纳] 双时空状态机思想 → 我们的静默时段升级为显式状态："Kaoru 睡了"时 UI 同步变安静、主动消息停发（吃药豁免）
- [未来] 2D 场景背景（昼夜呼应静默时段）
- [不采纳] OpenWebUI 多后端/多用户底座——只取交互设计，不取技术底座

#### InternalBeyond（情感连续性空间）

**定位**：离线单文件 HTML 个人网站，11 个模块组成的"情感连续性"空间；数据全本地、一键导入导出。

**关键机制**：
- **会遗忘的记忆**：星图可视化 + 自然衰减（淡出但不删除）+ 上下文自动注入 + Auto Memory（对话后自动沉淀新记忆）
- **Letters 书信模块**：AI 先读用户资料/日志再写回信——异步、错时、读-写分离
- Calendar：纪念日/生日/计划 + 月相节气——把"日子"变成共同记忆载体
- Tea 茶歇：基于依恋理论等设计 25 种氛围组合的情感对话空间——情绪调节优先于信息效率
- 双主题（白昼/黑夜）同一房间两态，界面色调同步

**对 Wisteria**：
- [采纳] **自然衰减记忆**：卡片带权重，随时间衰减、被提及即回温——补上我们三层记忆缺的"遗忘曲线"
- [采纳] **Auto Memory**：睡前记录、吃药状态、日程顺延在当天结束后自动生成候选记忆卡片，不依赖手动整理
- [采纳] Letters 的**读-写分离流程** = 月末信的魂：先汇总当月（连续天数/吃药完成率/顺延的日程/睡前记录），再生成信
- [采纳] 月历叠加共同纪念日（首次使用日、连续 100 天里程碑）
- [不采纳] 单文件 HTML 形态、10 路 API、换装/立绘/塔罗/桌宠
- [未来] Tea 的"先共情再执行"压缩为 3~5 个情感状态词（吃药提醒先问候）

### 第 2 组：SillyTavern / AIRI / PresenceKit / Tidefall

#### SillyTavern（角色扮演老牌前端）

**定位**：本地 Node.js 角色扮演 Web 前端，300+ 贡献者，事实上定义了"角色卡/世界书"标准。

**关键机制**：
- **角色卡 V3**：字段刻意拆分——description（原样进系统提示）/ personality（性格标签）/ scenario / first_mes（开场白定语气）/ mes_example（示例对话，AI 模仿口吻）/ system_prompt / post_history_instructions / alternate_greetings
- **世界书 World Info 信号灯**：蓝灯=常驻（只建议核心 1-3 条）；绿灯=关键词出现在最近 N 条消息内激活；黄灯=出现在整个聊天历史激活；红灯=禁用。核心哲学：**不提就不占 token**
- Timed Effects：以"消息数"为单位的激活延迟/粘性/冷却
- 预算控制：多条目同时命中时按权重+顺序排序，受上下文百分比+绝对 token 双上限
- 长期一致性标准解法 = 世界书 + 滚动摘要（**在最早消息被挤出上下文之前就生成第一份摘要**，摘要必须人工校对）

**对 Wisteria**：
- [采纳] 角色卡字段拆分 → Kaoru 人格模板的结构参考（personality/scenario/first_mes/mes_example）
- [采纳] 信号灯哲学：检索卡仅在相关时注入（不提不占 token）
- [采纳] "多条目命中时的权重+顺序+预算封顶"→ 决定哪些记忆注入 Kaoru 的提示词
- [采纳] 消息数单位的冷却/粘性 → 吃药再提醒与主动消息防轰炸
- [采纳] "摘要尽早生成 + 人工可校对"→ 我们的夜间本地整合 + 记忆页可编辑
- [不采纳] 关键词正则 + 四种布尔过滤的复杂度（单用户文字场景用"主键+别名"即可）；向量匹配（本地 iOS 重且不可预测）
- [未来] PNG 封面 + JSON 元数据合一 → 可用于导出/备份格式

#### AIRI（数字生命容器，3 万星）

**定位**：自托管的"数字生命容器"（Neuro-sama 开源复刻），30+ LLM 提供商，桌面/浏览器运行。

**关键机制**：
- Tamagotchi 桌宠模式 = **"不打扰的在场"**：安静待在屏幕角落，随时可打断进入对话，聊完自动缩回。主动感的来源是"永远在线 + 即时可及"，而不是消息轰炸
- **"被记住才被关心"**：全量对话本地存储 + RAG 召回——官方案例："你提过感冒，她会记得提醒你吃药"（我们吃药提醒的现成论证）
- 主动感知上下文：把应用状态/游戏状态接入对话流，角色"看懂你在干嘛"再发起互动
- 四阶段实时语音管线 VAD→STT→LLM→TTS

**对 Wisteria**：
- [采纳] **主动消息绑定记忆命中**（"被记住才被关心"），而非随机搭话
- [采纳] "不打扰式在场 + 即时可及"作为通知策略哲学基准：少而准、点击即入对话
- [不采纳] 实时语音、Live2D/VRM、游戏智能体（文字优先、单用户本地）
- [未来] 低配上下文感知：经用户授权读健康/专注模式数据

#### PresenceKit ⚠️ 未检索到一手资料

**定位**（基于描述推断，建议 clone 复核）：Python + Tauri，数据全本地；长期记忆隔离、多世界梦境系统、桌宠窗口、主动发消息、小花园、ESP32。

**关键机制**（推断 + 同类项目佐证）：
- 主动消息由"亲密度数值 + 情绪状态 + 时间表 + 记忆事件"四源驱动，而非定时随机
- **梦境 = 记忆整合的人格化输出**：夜间整合包装成"做梦"，把纯文本整合变成有叙事感的陪伴事件
- 小花园 = 陪伴积累的可视化资产（tamagotchi 系核心设计："每天回来看看"的钩子）
- 记忆隔离按"世界级 namespace"严格分层，互不污染

**对 Wisteria**：
- [采纳] "梦境 = 夜间整合的可视化叙事"→ 早安简报以回想/做梦口吻带出昨晚整合
- [采纳] 三层记忆写入路径独立，单向沉淀，防自我污染
- [不采纳] 桌宠窗口、多世界、ESP32 外设
- [未来] 小花园思想轻量化：连续天数+月历+里程碑本身就是积累资产（月末信里"这个月第 N 次按时吃药"这类沉淀反馈）

#### Tidefall / Eventide（数字生命运行时）⚠️ Tidefall 未检索到一手资料

**定位**：Eventide = InquisiMind/digital-life——让 LLM"像生命一样持续存在"的运行时框架，核心理念"LLM 只是大脑皮层，运行时系统才是生命主体"。Tidefall 为基于它的 Supabase 全自动方案（实时数值、24h 曲线、周期变化可视化、换肤）。

**关键机制**（Eventide 一手文档）：
- **唤醒四事件 + 差异化上下文注入**：message（全量 ~5KB）/ timer / vital_threshold / birth（只注入 ~1KB 唤醒提示）——**不同的唤醒理由需要不同的上下文深度**
- rest() 主动休息 + 闹钟自唤醒：模型必须显式指定 until；连续 N 轮只 sense 不 action 时系统强制要求休息（防瞎忙）
- **数值/状态系统**：显式 vitals（精力随休息恢复），`vital_threshold` 是一等唤醒事件——**数值变化能触发行为**
- 意识残留 + session 复用：休息前写下"留给下次自己的最后思考"；15 分钟内回来复用 session 接上
- **记忆代谢循环**：碎片日记 → 夜间整合 → 日摘要 → 反复出现沉淀为概念卡 → 碎片退役不占 token
- `_sys_tool` 伪装注入：上下文不硬塞 system 消息，而是包装成"模型自己之前调过的工具返回结果"——降低"被灌输指令"的扮演感

**对 Wisteria**：
- [采纳] **场景差异化上下文注入**：吃药提醒/睡前确认只带药单+最近状态 ≈1KB；闲聊才带全量 ≈2k token
- [采纳] **记忆代谢单向沉淀**：碎片→夜间整合→日摘要→候选卡片→（淡出不删）
- [采纳] **注入以 Kaoru 自己的记忆/回想口吻**，而非系统指令（`_sys_tool` 思想移植）
- [未来] 数值阈值驱动主动行为（主动档位 = 数值区间映射，可解释）；意识残留（"锁屏再开接着聊"）；24h 一日曲线面板（数值+吃药/事件标注）
- [不采纳] 全自动自唤醒循环（iOS 本地 + 用户主导节奏）、Supabase 后端

### 第 3 组：awesome-ai-companion 汇总清单（生态全景）

**清单结构**（11 大类）：聊天客户端/工作台、虚拟手机与伴侣空间、后台心跳与主动消息、记忆/身份/情绪状态、语音/形象/实体、感知、现实世界集成/MCP、游戏世界、共同活动与媒体、社区论坛、连续性/数据主权。

**社区主流模式**：
- **记忆 5 种做法**：① 混合检索记忆库（向量+BM25+情绪标注+遗忘曲线，Ombre-Brain）② 原文为真源、向量只作索引（Paramecium）③ 分层记忆+可视化策展面板（Aelios）④ LLM 自我反思"什么值得记住"（Aura）⑤ 日历化分层摘要+"睡眠"整合（kiwi-mem / 白守 BaiShou）
- **主动消息 4 种做法**：漂移轴阈值状态机（积温 jiwen）/ 统计学时机推断（revive-companion）/ 心跳唤醒→AI 决定发不发（dylan-heartbeat）/ 静默时段 DND（astrbot 插件）——静默时段是社区共识
- **连续性机制**：连击 streak（Phosphene）、关系亲密度模型（Aura）、情绪状态机（Aura）、日记/编年史/信件（KI-CO / InternalBeyond）、日/周/月时间线可视化（Journal / NAVI）、数据主权（导出/人格蒸馏）

**与 Wisteria 定位相似的项目**（无完全同位——"温柔恋人 + 生活管家 + 单用户本地 iOS"在生态中是空白）：
- **Aura**（最接近，重合 ~70%）：Android 本地 AI 陪伴 App——跨会话记忆 + 情绪状态机 + 亲密度模型 + Health Connect 步数/心率/睡眠 + 定时提醒 + 记忆室可视化 + JSON 全量导出。**License Private：设计可借鉴，代码不可抄**
- **白守 BaiShou**：Flutter + SQLite 本地日记 → 有记忆的 AI 伴侣；日→周→月→季→年层级总结——验证了我们的周分析/月末信流水线的 Flutter 本地可行性
- **ZeroChat**：Flutter + 主动消息 + 定时任务——Flutter 同栈工程结构最直接的参考（MIT）
- Phosphene：任务/积分/连击/成就（MIT）——连击正例，但其积分商城气质与温柔人设相悖

**对 Wisteria**：
- [采纳] 原文为真源（Paramecium）：卡片存原文 + SQLite FTS5 全文检索，防摘要污染
- [采纳] reflection 写入口（Aura）：LLM 判断"什么值得记住"后写入，用户可编辑纠正
- [采纳] 亲密度模型（Aura）：纯 prompt 注入，影响称呼/语气/建议倾向——最廉价的陪伴感机制
- [采纳] 轻量情绪状态机（Aura）：Kaoru 从客观数据感知状态（睡眠时长/链完成度），注入周分析；**不向用户收集打分**
- [采纳] 两类提醒区分（elroy）：context-based（日链顺延）vs timing-based（吃药硬定时）
- [不采纳] 积分商城（Phosphene 商城气质）、身体周期多驱力引擎（Eventide NSFW 倾向）、虚拟手机朋友圈、MCP 服务端概念
- [未来] HealthKit 健康数据注入、本地小模型离线模式、共读/文字小游戏、文字情绪皮肤
